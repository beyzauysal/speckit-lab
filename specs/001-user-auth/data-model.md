# Data Model: User Authentication System

**Feature**: User Authentication System (001-user-auth)  
**Date**: 2026-05-08  
**Status**: Phase 1a Data Model Complete

## Entity Relationship Diagram

```
User (1) ──┬─→ (many) AuthToken
           ├─→ (many) RefreshToken  
           ├─→ (many) SessionMetadata
           ├─→ (many) LoginAttempt
           ├─→ (many) PasswordReset
           ├─→ (many) DeletionRequest
           └─→ (many) AuditLog
```

## Entity Definitions

### 1. User

**Purpose**: Core user account entity; stores credentials and account state

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| user_id | UUID | PK | Unique identifier; used in tokens |
| email | VARCHAR(255) | UNIQUE, NOT NULL | Login identifier; RFC 5322 validated |
| password_hash | CHAR(60) | NOT NULL | bcrypt hash (cost 10); 60-char fixed width |
| created_at | TIMESTAMP | NOT NULL, DEFAULT NOW() | Account creation time |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT NOW() | Last modification time |
| is_active | BOOLEAN | NOT NULL, DEFAULT TRUE | Soft-delete flag (false = deactivated by user) |
| failed_login_attempts | INT | DEFAULT 0 | Counter for brute force detection |
| account_locked_until | TIMESTAMP | NULL | Time when account lockout expires; NULL = not locked |

**Indexes**:
- `UNIQUE (email)` - Fast email lookups during login
- `(account_locked_until)` - Cleanup queries to find expired lockouts
- `(failed_login_attempts)` - Query locked accounts

**Validation Rules**:
- email: RFC 5322 format + no duplicate registrations
- password_hash: Generated by bcrypt.hash(password, 10)
- is_active: TRUE for new registrations unless explicitly deactivated

**Relationships**:
- 1:N with AuthToken (user can have multiple active JWT tokens)
- 1:N with RefreshToken (user can have multiple 30-day refresh tokens)
- 1:N with SessionMetadata (user can have multiple concurrent sessions)
- 1:N with LoginAttempt (history of all login attempts)
- 1:N with PasswordReset (pending password resets)
- 1:N with DeletionRequest (pending account deletion)
- 1:N with AuditLog (all auth events)

**State Transitions**:
- NEW → ACTIVE (on registration)
- ACTIVE → LOCKED (after 5 failed login attempts)
- LOCKED → ACTIVE (after 15 minutes OR via unlock link)
- ACTIVE → DELETION_PENDING (user requests deletion)
- DELETION_PENDING → DELETED (after 30-day grace period)

### 2. AuthToken

**Purpose**: Tracks issued JWT tokens; enables revocation (logout, password reset)

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| token_id | UUID | PK | Unique identifier for this token |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user owns this token |
| token_hash | CHAR(64) | NOT NULL | SHA-256 hash of JWT (for secure storage; token itself never stored) |
| expires_at | TIMESTAMP | NOT NULL | Token expiry time (issued_at + 24 hours) |
| issued_at | TIMESTAMP | NOT NULL | Token creation time |
| revoked_at | TIMESTAMP | NULL | Revocation time; NULL = active |

**Indexes**:
- `(user_id, expires_at)` - Find active tokens for user
- `(expires_at)` - Cleanup queries for expired tokens
- `(revoked_at)` - Query revoked tokens (audit)

**Validation Rules**:
- token_hash: SHA-256 hash of JWT (never store JWT plaintext)
- expires_at: Must be 24 hours after issued_at (enforced in code)
- revoked_at: Set on logout or password reset; NULL = active

**Lifecycle**:
- Created at login (POST /login)
- Validated on protected endpoints (middleware)
- Revoked on logout (POST /logout) or password reset
- Auto-expired after 24 hours (cleanup job)

**Query Patterns**:
- Check if token is revoked: `SELECT revoked_at FROM AuthToken WHERE token_hash = ?`
- Find all active tokens for user (for logout-all): `SELECT * FROM AuthToken WHERE user_id = ? AND revoked_at IS NULL AND expires_at > NOW()`

### 3. RefreshToken

**Purpose**: Long-lived tokens (30 days) for session continuation without password re-entry

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| refresh_token_id | UUID | PK | Unique identifier |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user owns this token |
| token_hash | CHAR(64) | NOT NULL | SHA-256 hash of refresh token |
| expires_at | TIMESTAMP | NOT NULL | Token expiry (issued_at + 30 days) |
| issued_at | TIMESTAMP | NOT NULL | Creation time |
| revoked_at | TIMESTAMP | NULL | Revocation time (password reset); NULL = active |
| last_used_at | TIMESTAMP | NULL | Last successful refresh; NULL = unused |

**Indexes**:
- `(user_id, expires_at)` - Find active refresh tokens for user
- `(token_hash)` - Lookup on refresh endpoint
- `(revoked_at)` - Track revoked tokens

**Validation Rules**:
- expires_at: 30 days from issued_at
- revoked_at: Set on password reset (all user tokens revoked)
- last_used_at: Updated on successful refresh (for audit trail)

**Lifecycle**:
- Created at login (issued alongside JWT)
- Used to obtain new JWT via POST /refresh (no password required)
- Revoked on password reset (all refresh tokens invalidated)
- Auto-expired after 30 days

**Query Patterns**:
- Refresh token: `SELECT * FROM RefreshToken WHERE token_hash = ? AND revoked_at IS NULL AND expires_at > NOW()`
- Revoke all on password reset: `UPDATE RefreshToken SET revoked_at = NOW() WHERE user_id = ?`

### 4. SessionMetadata

**Purpose**: Track concurrent sessions across devices; enables per-device logout and security audit

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| session_id | UUID | PK | Unique session identifier |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user owns this session |
| device_name | VARCHAR(255) | NOT NULL | User-provided device name (e.g., "Chrome on MacBook") |
| device_type | ENUM | NOT NULL | One of: 'web', 'mobile_ios', 'mobile_android', 'desktop' |
| ip_address | VARCHAR(45) | NOT NULL | Client IP (supports IPv4 + IPv6) |
| last_activity_at | TIMESTAMP | NOT NULL | Last request timestamp; updated on activity |
| created_at | TIMESTAMP | NOT NULL | Session creation time |
| user_agent | VARCHAR(500) | NOT NULL | Browser/client user agent string |

**Indexes**:
- `(user_id, created_at DESC)` - List all sessions for user
- `(last_activity_at)` - Cleanup inactive sessions (>30 days)

**Validation Rules**:
- device_type: One of predefined enums
- ip_address: Valid IPv4 or IPv6 format
- last_activity_at: Updated on every authenticated request

**Lifecycle**:
- Created at login (POST /login)
- Updated on every API call using this token (middleware)
- Deleted on logout (DELETE /sessions/:id)
- Auto-cleaned after 30 days of inactivity

**Query Patterns**:
- List all sessions for user: `SELECT * FROM SessionMetadata WHERE user_id = ? ORDER BY created_at DESC`
- Logout from specific device: `DELETE FROM SessionMetadata WHERE session_id = ?`

### 5. LoginAttempt

**Purpose**: Track failed login attempts for brute force detection; triggers account lockout

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| attempt_id | UUID | PK | Unique identifier |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user attempted login |
| attempt_timestamp | TIMESTAMP | NOT NULL | When attempt occurred |
| success | BOOLEAN | NOT NULL | TRUE = valid password, FALSE = invalid password |
| ip_address | VARCHAR(45) | NOT NULL | Client IP address |
| user_agent | VARCHAR(500) | NOT NULL | Browser/client identifier |

**Indexes**:
- `(user_id, attempt_timestamp DESC)` - Query recent attempts for user
- `(user_id, success)` - Count failed attempts for lockout check
- `(attempt_timestamp)` - Cleanup old records

**Validation Rules**:
- success: Set based on password verification result
- attempt_timestamp: Set at login attempt time (not later)

**Lifecycle**:
- Created on every login attempt (successful or failed)
- Used to trigger account lockout (5 failed = 15min lock)
- Cleaned up after 90 days (no retention required beyond fraud investigation)

**Query Patterns**:
- Count failed attempts in last hour: `SELECT COUNT(*) FROM LoginAttempt WHERE user_id = ? AND success = FALSE AND attempt_timestamp > NOW() - INTERVAL 1 HOUR`
- Determine if account should be locked: `SELECT COUNT(*) FROM LoginAttempt WHERE user_id = ? AND success = FALSE AND attempt_timestamp > NOW() - INTERVAL 1 HOUR` → If count >= 5, lock

**Brute Force Logic** (enforced in AuthService):
```
1. Query failed attempts in last 24h
2. If count >= 5: Check account_locked_until
   - If locked_until > NOW(): Reject login (account locked)
   - If locked_until <= NOW(): Clear counter, allow login attempt
3. On failed password: Increment counter; if now >= 5, set account_locked_until = NOW() + 15 min
```

### 6. QueuedEmail

**Purpose**: Queue email delivery for reliable async sending; retry on failure

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| email_id | UUID | PK | Unique identifier |
| recipient_email | VARCHAR(255) | NOT NULL | Destination email address |
| email_type | ENUM | NOT NULL | One of: 'registration_confirmation', 'password_reset', 'account_locked', 'deletion_notice' |
| template_data | JSONB | NOT NULL | Template variables (e.g., `{"reset_link": "...", "user_name": "..."}`) |
| retry_count | INT | DEFAULT 0 | Number of delivery attempts |
| last_attempt_at | TIMESTAMP | NULL | Timestamp of last delivery attempt |
| next_retry_at | TIMESTAMP | NULL | When to retry next |
| status | ENUM | NOT NULL | One of: 'pending', 'sent', 'failed', 'dead_letter' |
| created_at | TIMESTAMP | NOT NULL | Email queued time |
| expires_at | TIMESTAMP | NOT NULL | When to stop retrying (created_at + 24h) |

**Indexes**:
- `(status, next_retry_at)` - Find emails ready to retry
- `(recipient_email, created_at DESC)` - Query emails sent to user
- `(email_type)` - Analytics (how many password resets, etc.)

**Validation Rules**:
- email_type: One of predefined types
- template_data: Valid JSON matching email type template
- retry_count: 0-3 attempts
- expires_at: 24 hours from creation

**Lifecycle**:
- Created when email needs to be sent (registration, password reset, account locked, deletion)
- BullMQ worker processes queue (retries up to 3 times)
- Exponential backoff: 1min → 5min → 1hour delays
- Auto-deleted after 30 days (retention for audit)

**Query Patterns**:
- Find pending emails ready to retry: `SELECT * FROM QueuedEmail WHERE status = 'pending' AND next_retry_at <= NOW()`
- Count delivered emails: `SELECT COUNT(*) FROM QueuedEmail WHERE email_type = 'password_reset' AND status = 'sent' AND created_at > NOW() - INTERVAL 30 DAY`

### 7. DeletionRequest

**Purpose**: Track account deletion requests; enforce 30-day grace period before data purge

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| deletion_id | UUID | PK | Unique identifier |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user requested deletion |
| request_timestamp | TIMESTAMP | NOT NULL | When deletion was requested |
| grace_period_ends_at | TIMESTAMP | NOT NULL | When deletion will execute (request_timestamp + 30 days) |
| executed_at | TIMESTAMP | NULL | When deletion actually happened; NULL = pending |
| cancelled_at | TIMESTAMP | NULL | When user cancelled deletion; NULL = not cancelled |

**Indexes**:
- `(user_id)` - Find pending deletion for user
- `(grace_period_ends_at)` - Batch job to find deletions ready to execute
- `(executed_at)` - Query completed deletions (audit)

**Validation Rules**:
- grace_period_ends_at: Exactly 30 days from request_timestamp
- executed_at: Set when batch deletion job completes
- cancelled_at: Set if user cancels before grace period expires

**Lifecycle**:
1. User requests deletion (DELETE /account) → Create DeletionRequest
2. Email reminder at day 0, 7, 14, 25 ("deletion pending, click to cancel")
3. User can cancel anytime before grace_period_ends_at (POST /account/delete/cancel)
4. Batch job runs daily after grace_period_ends_at:
   - Delete User, AuthToken, RefreshToken, SessionMetadata, LoginAttempt
   - Anonymize AuditLog (set user_id = NULL)
   - Set executed_at = NOW()

**Query Patterns**:
- Check if user has pending deletion: `SELECT * FROM DeletionRequest WHERE user_id = ? AND executed_at IS NULL AND cancelled_at IS NULL`
- Find deletions ready to execute: `SELECT * FROM DeletionRequest WHERE grace_period_ends_at <= NOW() AND executed_at IS NULL AND cancelled_at IS NULL`
- Cancel deletion: `UPDATE DeletionRequest SET cancelled_at = NOW() WHERE deletion_id = ? AND executed_at IS NULL`

### 8. AuditLog

**Purpose**: Immutable record of all authentication events; enables security investigation and compliance

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| log_id | UUID | PK | Unique identifier |
| user_id | UUID | FK → User.user_id (nullable) | Which user (NULL after deletion for anonymization) |
| event_type | ENUM | NOT NULL | One of: 'registration', 'login_success', 'login_failed', 'logout', 'token_refresh', 'password_reset', 'account_locked', 'account_unlocked', 'deletion_requested', 'deletion_executed' |
| event_timestamp | TIMESTAMP | NOT NULL | When event occurred |
| ip_address | VARCHAR(45) | NOT NULL | Client IP |
| user_agent | VARCHAR(500) | NOT NULL | Browser/client identifier |
| details | JSONB | NOT NULL | Event-specific data (no PII): `{"device_id": "...", "session_id": "...", "reason": "..."}` |
| retention_until | TIMESTAMP | NOT NULL | Delete after this date (24 months from creation) |

**Indexes**:
- `(user_id, event_timestamp DESC)` - Audit trail for user
- `(event_type, event_timestamp)` - Analytics (login failures per hour, etc.)
- `(retention_until)` - Cleanup expired logs

**Validation Rules**:
- event_type: One of predefined event types
- details: No PII (no email, password, token values)
- retention_until: 24 months (730 days) from creation
- user_id: Anonymized (set to NULL) after account deletion per GDPR

**Lifecycle**:
- Created on every auth event (immutable insert-only table)
- Queryable by admins/compliance officers for investigations
- Auto-deleted 24 months after creation

**Query Patterns**:
- Investigate account takeover: `SELECT * FROM AuditLog WHERE user_id = ? AND event_timestamp > NOW() - INTERVAL 7 DAY ORDER BY event_timestamp DESC`
- Count failed logins per hour: `SELECT COUNT(*) FROM AuditLog WHERE event_type = 'login_failed' AND event_timestamp > NOW() - INTERVAL 1 HOUR GROUP BY DATE_TRUNC('hour', event_timestamp)`
- Anonymize after deletion: `UPDATE AuditLog SET user_id = NULL, email = NULL WHERE user_id = ? AND event_timestamp < NOW() - INTERVAL 24 MONTH`

### 9. PasswordReset

**Purpose**: One-time password reset tokens; enables account recovery

**Fields**:

| Field | Type | Constraints | Purpose |
|-------|------|-----------|---------|
| reset_id | UUID | PK | Unique identifier |
| user_id | UUID | FK → User.user_id, NOT NULL | Which user is resetting password |
| token_hash | CHAR(64) | NOT NULL | SHA-256 hash of reset token (sent in email) |
| expires_at | TIMESTAMP | NOT NULL | Token expiry (created_at + 1 hour) |
| used_at | TIMESTAMP | NULL | When password was successfully reset; NULL = unused |
| created_at | TIMESTAMP | NOT NULL | When reset was requested |

**Indexes**:
- `(token_hash)` - Lookup reset link in email
- `(user_id, created_at DESC)` - Find recent reset requests for user
- `(expires_at)` - Cleanup expired resets

**Validation Rules**:
- token_hash: SHA-256 hash (never store plaintext token)
- expires_at: 1 hour from created_at
- used_at: Set on successful password update

**Lifecycle**:
1. User requests password reset (POST /password-reset?email=...) 
2. System generates random token, creates PasswordReset record with token_hash
3. Email sent with reset link (token in URL: /password-reset/TOKEN?user_id=...)
4. User clicks link, views password reset form
5. User submits new password (PUT /password-reset/:token)
6. System validates token (not expired, not already used), updates User.password_hash
7. Sets PasswordReset.used_at = NOW() (one-time use)
8. Revokes all AuthToken + RefreshToken for user (force re-login)

**Query Patterns**:
- Validate reset token: `SELECT * FROM PasswordReset WHERE token_hash = ? AND expires_at > NOW() AND used_at IS NULL`
- Mark as used: `UPDATE PasswordReset SET used_at = NOW() WHERE reset_id = ?`
- Cleanup expired: `DELETE FROM PasswordReset WHERE expires_at < NOW() AND used_at IS NULL` (auto-deleted after 1h)

## Database Schema (DDL)

```sql
-- User accounts
CREATE TABLE users (
  user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash CHAR(60) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  failed_login_attempts INT NOT NULL DEFAULT 0,
  account_locked_until TIMESTAMP NULL,
  CHECK (char_length(email) > 0 AND char_length(email) <= 255)
);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_account_locked_until ON users(account_locked_until);

-- JWT tokens
CREATE TABLE auth_tokens (
  token_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  token_hash CHAR(64) NOT NULL UNIQUE,
  expires_at TIMESTAMP NOT NULL,
  issued_at TIMESTAMP NOT NULL,
  revoked_at TIMESTAMP NULL
);
CREATE INDEX idx_auth_tokens_user_id_expires_at ON auth_tokens(user_id, expires_at);
CREATE INDEX idx_auth_tokens_token_hash ON auth_tokens(token_hash);

-- Refresh tokens
CREATE TABLE refresh_tokens (
  refresh_token_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  token_hash CHAR(64) NOT NULL UNIQUE,
  expires_at TIMESTAMP NOT NULL,
  issued_at TIMESTAMP NOT NULL,
  revoked_at TIMESTAMP NULL,
  last_used_at TIMESTAMP NULL
);
CREATE INDEX idx_refresh_tokens_user_id ON refresh_tokens(user_id, expires_at);
CREATE INDEX idx_refresh_tokens_token_hash ON refresh_tokens(token_hash);

-- Session metadata
CREATE TABLE session_metadata (
  session_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  device_name VARCHAR(255) NOT NULL,
  device_type VARCHAR(50) NOT NULL CHECK (device_type IN ('web', 'mobile_ios', 'mobile_android', 'desktop')),
  ip_address VARCHAR(45) NOT NULL,
  last_activity_at TIMESTAMP NOT NULL DEFAULT NOW(),
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  user_agent VARCHAR(500) NOT NULL
);
CREATE INDEX idx_session_metadata_user_id ON session_metadata(user_id, created_at DESC);

-- Login attempts
CREATE TABLE login_attempts (
  attempt_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  attempt_timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
  success BOOLEAN NOT NULL,
  ip_address VARCHAR(45) NOT NULL,
  user_agent VARCHAR(500) NOT NULL
);
CREATE INDEX idx_login_attempts_user_id_timestamp ON login_attempts(user_id, attempt_timestamp DESC);

-- Queued emails
CREATE TABLE queued_emails (
  email_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  recipient_email VARCHAR(255) NOT NULL,
  email_type VARCHAR(50) NOT NULL CHECK (email_type IN ('registration_confirmation', 'password_reset', 'account_locked', 'deletion_notice')),
  template_data JSONB NOT NULL,
  retry_count INT NOT NULL DEFAULT 0,
  last_attempt_at TIMESTAMP NULL,
  next_retry_at TIMESTAMP NULL,
  status VARCHAR(50) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'sent', 'failed', 'dead_letter')),
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  expires_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_queued_emails_status_retry ON queued_emails(status, next_retry_at);

-- Account deletion requests
CREATE TABLE deletion_requests (
  deletion_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  request_timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
  grace_period_ends_at TIMESTAMP NOT NULL,
  executed_at TIMESTAMP NULL,
  cancelled_at TIMESTAMP NULL
);
CREATE INDEX idx_deletion_requests_user_id ON deletion_requests(user_id);
CREATE INDEX idx_deletion_requests_grace_period ON deletion_requests(grace_period_ends_at) WHERE executed_at IS NULL;

-- Audit logs
CREATE TABLE audit_logs (
  log_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NULL REFERENCES users(user_id) ON DELETE SET NULL,
  event_type VARCHAR(50) NOT NULL,
  event_timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
  ip_address VARCHAR(45) NOT NULL,
  user_agent VARCHAR(500) NOT NULL,
  details JSONB NOT NULL,
  retention_until TIMESTAMP NOT NULL
);
CREATE INDEX idx_audit_logs_user_id_timestamp ON audit_logs(user_id, event_timestamp DESC);
CREATE INDEX idx_audit_logs_retention ON audit_logs(retention_until);

-- Password resets
CREATE TABLE password_resets (
  reset_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  token_hash CHAR(64) NOT NULL UNIQUE,
  expires_at TIMESTAMP NOT NULL,
  used_at TIMESTAMP NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_password_resets_token_hash ON password_resets(token_hash);
```

## Validation & Constraints

### Email Validation
- RFC 5322 format (simplified): `^[^@\s]+@[^@\s]+\.[^@\s]+$`
- Lowercase storage (case-insensitive lookups)
- Unique constraint at database level

### Password Validation
- Minimum 8 characters
- Require: uppercase (A-Z), lowercase (a-z), number (0-9), special character (!@#$%^&*)
- Must not contain user email
- Cannot reuse last 3 passwords (PasswordHistory table optional)

### Token Expiry Validation
- JWT: 24 hours from issued_at
- Refresh Token: 30 days from issued_at
- Password Reset: 1 hour from created_at
- Session: 30 days inactivity auto-cleanup

## Compliance & Privacy

- **GDPR Right to Erasure**: Delete user data within 30 days of request; anonymize audit logs
- **CCPA Right to Delete**: Same as GDPR
- **Data Retention**: Audit logs retained 24 months; email queue retained 30 days; other transient data cleaned up on expiry
- **Encryption**: password_hash (bcrypt format); token_hash (SHA-256); TLS for transit
- **PII Handling**: Email stored unhashed; password never stored plaintext; token never stored plaintext

- List user sessions: <10ms (indexed)

**Scaling Assumptions**:

- 1B audit log entries: Archive logs >2 years to cold storage
